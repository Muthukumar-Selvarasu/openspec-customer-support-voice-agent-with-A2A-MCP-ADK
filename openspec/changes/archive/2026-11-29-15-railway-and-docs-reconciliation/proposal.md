# Proposal

## Why

After archiving `08-railway-deploy`, `12-design-system-ui`, and `16-dependency-and-telemetry-upgrades`, and addressing the core security/voice bugs in Changes `13` and `14`, several Railway runtime defects, database idempotency gaps, spec/metadata omissions, and documentation drifts from the 2026-11-19 and 2026-11-26 EGM drift reports still remain:

1. **Railway Neon SSL, Phoenix link/auth exposure & missing service healthchecks (`.railway/railway.py`, `scripts/start-toolbox.mjs`, `src/static/architecture.html`, `src/api/web.py`):**
   - `scripts/start-toolbox.mjs` discards `DATABASE_URL` query parameters (dropping `sslmode=require` required by Neon) when generating `/tmp/tools.yaml`.
   - `.railway/railway.py` sets `PHOENIX_PUBLIC_URL` to Railway's internal private hostname (`_private("phoenix")`), which is unreachable from a user's browser, while `src/static/architecture.html` hardcodes `href="http://localhost:6006"` on `"Open Phoenix"`.
   - Simultaneously, `.railway/railway.py` sets `PHOENIX_ENABLE_AUTH: "false"` — exposing Phoenix on a public Railway HTTPS domain without authentication would leak customer emails, prompts, SQL queries, and addresses in traces to the public internet.
   - Only `web-voice-app` declares a Railway `healthcheck`; `mcp-toolbox`, `a2a-judge`, `a2a-masker`, and `phoenix` omit healthcheck paths, and `src/api/web.py` line 189 hardcodes `"Toolbox :5000"` in the inspector path.
2. **Destructive seed script, Neon role grants & `action_type` naming mismatch (`mcp_toolbox/seed.sql`, `mcp_toolbox/tools.yaml`, `run.sh`):**
   - `mcp_toolbox/seed.sql` begins with `DROP TABLE IF EXISTS` and bare `CREATE TABLE` / `INSERT INTO`, risking data loss if re-run against Neon, AND runs unguarded `GRANT ... TO toolbox_user;` which fails on Neon Postgres (`neondb_owner`) where role `toolbox_user` does not exist.
   - `mcp_toolbox/tools.yaml` AND `run.sh`'s `.run/tools.yaml` heredoc (line 153) list example action types `CANCEL_ORDER, RETURN_ORDER, UPDATE_ADDRESS, UPDATE_PROFILE` whereas `src/core/prompts.py` and `docs/02-problem-metrics.md` use `UPDATE_ORDER_STATUS, RETURN_ITEM, UPDATE_DELIVERY_ADDRESS, UPDATE_PROFILE_DETAILS`.
3. **Local Podman ops, architecture SVG, CSS leftovers & spec metadata drift (`run.sh`, `compose.yaml`, `src/static/architecture.svg`, `src/static/theme.css`, `openspec/specs/`):**
   - `./run.sh down` and `./run.sh ps` ignore `compose.runtime.yaml` when host port `5000` is busy; `./run.sh` unconditionally starts `phoenix` despite `README.md` calling Phoenix optional; and `compose.yaml` `web` service does not forward `VOICE_STT_LIVE_MODEL`, `VOICE_PRICE_STT_IN`, or `VOICE_PRICE_STT_OUT`.
   - `src/static/architecture.svg` still labels STT as `gemini-3.1-flash-lite`, Sanitizer as `regex blocker`, and Data Masker as `ADK agent · :10003`, and none of the three guardrail nodes (`Sanitizer`, `Security Judge`, `Data Masker`) or the `architecture.html` legend explicitly displays a **"Guardrail"** badge/label — causing reviewers inspecting `/architecture` to miss that guardrails are implemented.
   - `src/static/theme.css` retains a stale `(light-only)` comment and unused `.ds-aurora-wrap` rule; `web-and-cli-channels/spec.md` retains the contradictory heading `"Light-Only Design System Surfaces and Typography"` and falsely implies `docs/DESIGN.md` defines the dark palette (whereas `docs/DESIGN.md` is a light-only FDE Companion reference and the dark palette is app-specific).
   - `database-and-mcp-tools`, `ops-and-deployment`, and `railway-deploy` omit `.env.example` live-STT/Railway keys, `pytest.ini` `addopts = -p no:phoenix`, `.railway/requirements.txt`, `.railway/railway.py`, `Dockerfile.toolbox`, `scripts/start-toolbox.mjs`, and PTT (`0 ms`) / Quick (`400 ms`) settle in `Local Full Cascade`.
4. **FDE documentation & `README.md` lag (`README.md`, `docs/`):**
   - `README.md` still states `phoenix` stays private (contradicting authenticated public `PHOENIX_PUBLIC_URL`), describes `seed.sql` as destructive one-shot, omits `.railway/requirements.txt` and Railway packaging files, and refers to `08-railway-deploy` as an unarchived change.
   - `docs/ENGAGEMENT.md`, `docs/01-discovery.md`, `docs/02-problem-metrics.md`, `docs/03-poc.md`, and `docs/DEVELOPMENT_STEPS.md` still reference removed GCP DLP / Model Armor SDKs, legacy `agent_cli.py`, wrong `cs_agent/voice/cost.py` path, outdated STT model/prices (`gemini-3.1-flash-lite` `$0.30/$0.40` vs `gemini-3.1-flash-live-preview` `$3.00/$4.50`), `BARGE_RMS = 0.05`, Hold/Resume controls, old cyan/green/red SVG colors, `GET /api/session` (actually `POST /api/session`), non-existent `docs/06-qa-uat/eval-report.md` / `benchmarking_voice_agents/`, old schema DDL (missing both `customer_orders` and `actions_log` FKs), inaccurate CLI Layer 2b guardrail / 4-stage loader claims, plain-text ` · premium` header indicator, actual blocker flood bounds (`A{64,}`, `(?:%s){2,}`), actual `total_response` formula (`stt + answer_sec`), demo-only bare `user_id` session scope note, and omit `12-design-system-ui` plus Changes `13`–`16` in `DEVELOPMENT_STEPS.md`.

> **Change 16 coordination note:** This change runs after `16-dependency-and-telemetry-upgrades` is archived and intentionally preserves Change 16's pinned `phoenix:version-22.0.1` tag, loopback `127.0.0.1:6006:6006` Compose binding, `-c constraints.txt` installs, and removal of `arize-phoenix` from `requirements.txt` and `Dockerfile`.

> **Review decision to confirm before apply (Decision #4):** This proposal updates `docs/` to match the implemented local-regex security stack, defense-in-depth customer-support domain-scope guardrail added in Change `13` (Layer 2 A2A Judge `OFF_TOPIC` verdict + `SQL_PROMPT_INSTRUCTION` domain scope across Web, Voice, and CLI — without a separate standalone Layer 2b microservice), 2-stage CLI (after Change 14 removes the fake order-loading sleep), static demo account login hints, and demo-only bare `user_id` auth scope (rather than re-introducing GCP SDKs). If you want clickable demo account login chips in `src/static/index.html`, we can easily add a small task via `opsx update 15-railway-and-docs-reconciliation`.

## What Changes

- **Preserve Neon `sslmode=require` in MCP Toolbox startup (`scripts/start-toolbox.mjs`):** Forward `DATABASE_URL` query parameters (such as `sslmode=require`) into `/tmp/tools.yaml` via the `@toolbox-sdk/server` Postgres `queryParams` block (verified against `@toolbox-sdk/server@1.5.0`) so Neon TLS connections work reliably on Railway.
- **Secure browser-reachable Railway Phoenix link & service healthchecks (`.railway/railway.py`, `src/api/web.py`, `src/static/architecture.html`):** Wire `PHOENIX_PUBLIC_URL` in `.railway/railway.py` to `https://${{phoenix.RAILWAY_PUBLIC_DOMAIN}}` while enabling Phoenix authentication on Railway (`PHOENIX_ENABLE_AUTH: "true"`, `PHOENIX_SECRET: preserve()`, keeping `phoenix:version-22.0.1` from Change 16 and local Compose `PHOENIX_ENABLE_AUTH: "false"` on loopback); add explicit `healthcheck` paths to `mcp-toolbox`, `a2a-judge`, `a2a-masker`, and `phoenix`; serve/inject `PHOENIX_PUBLIC_URL` into `src/static/architecture.html` so `"Open Phoenix"` no longer hardcodes `http://localhost:6006`; and replace hardcoded `"Toolbox :5000"` in `src/api/web.py` (`TOOLS[name]["path"]`) with a dynamic/generic `"MCP Toolbox"` label.
- **Make `mcp_toolbox/seed.sql` idempotent & Neon-role-safe, and align `mcp_toolbox/tools.yaml` + `run.sh`:** Convert `mcp_toolbox/seed.sql` to `CREATE TABLE IF NOT EXISTS`, `CREATE INDEX IF NOT EXISTS`, idempotent inserts (`ON CONFLICT DO NOTHING`), and `pg_roles`-guarded `GRANT ... TO toolbox_user` so it runs cleanly on both Neon and local Podman Postgres; align `action-log` `action_type` examples in both `mcp_toolbox/tools.yaml` and `run.sh`'s `.run/tools.yaml` heredoc with `src/core/prompts.py`.
- **Fix local Podman ops, architecture SVG guardrail badges/labels & CSS leftovers (`run.sh`, `compose.yaml`, `src/static/architecture.svg`, `src/static/architecture.html`, `src/static/theme.css`):** Have `./run.sh down` and `./run.sh ps` honor `compose.runtime.yaml` when present; support `PHOENIX=false` / `--no-phoenix` in `./run.sh` so local Phoenix is genuinely optional; forward `VOICE_STT_LIVE_MODEL`, `VOICE_PRICE_STT_IN`, and `VOICE_PRICE_STT_OUT` in `compose.yaml`'s `web` service (preserving Change 16's `phoenix:version-22.0.1` and `127.0.0.1:6006:6006`); update stale STT/Sanitizer/Masker labels and add explicit **GUARDRAIL** badges/labels on Layers 1–3 (`Sanitizer`, `Security & Topic Judge`, `Data Masker`) in `src/static/architecture.svg` plus a `guardrail` legend entry in `src/static/architecture.html`; and remove the stale `(light-only)` comment and unused `.ds-aurora-wrap` block in `src/static/theme.css`.
- **Reconcile specs, `README.md` & FDE docs (`openspec/specs/`, `README.md`, `docs/`):** Rename the contradictory `"Light-Only"` requirement in `web-and-cli-channels` and accurately distinguish light tokens adapted from `docs/DESIGN.md` vs. the app-specific dark palette; preserve Change 16's `-c constraints.txt` / no-`arize-phoenix` wording in `ops-and-deployment` while adding Railway packaging files and PTT/Quick settle wording; document Railway packaging/auth/healthchecks and `.env.example`/`pytest.ini` additions in `railway-deploy` and `database-and-mcp-tools`; and bring `README.md`, `docs/ENGAGEMENT.md`, `docs/01-discovery.md`, `docs/02-problem-metrics.md`, `docs/03-poc.md`, and `docs/DEVELOPMENT_STEPS.md` (including `12`–`16`) fully in sync with the codebase.
